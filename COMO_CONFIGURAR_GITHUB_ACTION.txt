=============================================================
 COMO CONFIGURAR O GITHUB ACTION DESTA AVALIAÇÃO
=============================================================

O QUE ESSE WORKFLOW FAZ
-------------------------------------------------------------
Arquivo: .github/workflows/avaliacao.yml

Sempre que houver um push em qualquer branch deste repositório
(ou quando disparado manualmente pela aba "Actions"), o GitHub
Action:

  1. Faz o checkout do código e instala as dependências (npm ci)
  2. Builda a aplicação React (npm run build)
  3. Sobe a aplicação (vite preview) e roda os 20 testes do
     Cypress definidos em cypress/e2e/avaliacao.cy.js
  4. Gera um resumo do resultado (cypress/relatorio/resumo.json),
     juntando o placar dos testes com os dados preenchidos em
     cypress/fixtures/candidato.json
  5. Envia um e-mail com esse resumo para
     francisco.marreira@engesoftware.com.br
  6. Publica o relatório completo (HTML/screenshots) como
     artefato do próprio Action, para consulta depois

Importante: o e-mail é enviado SEMPRE (mesmo se algum teste
falhar, ou se o candidato ainda não tiver implementado nenhuma
questão) — o passo usa "if: always()" propositalmente.


PASSO 1 — CRIAR AS SECRETS DO REPOSITÓRIO (envio de e-mail)
-------------------------------------------------------------
O envio de e-mail usa a action "dawidd6/action-send-mail", que
precisa de um servidor SMTP configurado via Secrets do GitHub.

No repositório, vá em:
  Settings > Secrets and variables > Actions > New repository secret

Crie as 4 secrets abaixo:

  SMTP_SERVER    -> endereço do servidor SMTP
                    ex: smtp.gmail.com
  SMTP_PORT      -> porta do servidor SMTP
                    ex: 465 (SSL) ou 587 (TLS)
  SMTP_USERNAME  -> usuário/e-mail que vai autenticar e enviar
                    ex: seuemail@gmail.com
  SMTP_PASSWORD  -> senha de aplicativo (NÃO é a senha normal
                    da conta — veja o passo 2 se for usar Gmail)

Essas 4 secrets são obrigatórias para o passo "Enviar e-mail
com o resultado da avaliação" funcionar. Sem elas, o workflow
roda os testes normalmente, mas falha só no envio do e-mail.


PASSO 2 — GERAR UMA SENHA DE APP (SE USAR GMAIL)
-------------------------------------------------------------
O Gmail não aceita a senha normal da conta em integrações SMTP.
É preciso gerar uma "Senha de app":

  1. Ative a verificação em duas etapas na conta Google:
     https://myaccount.google.com/security
  2. Acesse: https://myaccount.google.com/apppasswords
  3. Crie uma senha de app para "Mail" / "Outro (nome
     personalizado)" — algo como "GitHub Actions - Avaliação"
  4. Copie a senha gerada (16 caracteres) e use como valor da
     secret SMTP_PASSWORD
  5. Use como SMTP_SERVER: smtp.gmail.com e SMTP_PORT: 465

Se preferir usar outro provedor (Outlook, SendGrid, Amazon SES,
um SMTP corporativo etc.), basta usar o host/porta/usuário/senha
correspondentes — a estrutura das secrets é a mesma.


PASSO 3 — CONFERIR O DESTINATÁRIO DO E-MAIL
-------------------------------------------------------------
O destinatário já está fixo no workflow (não é uma secret):

  .github/workflows/avaliacao.yml -> campo "to:"
  to: francisco.marreira@engesoftware.com.br

Se precisar trocar ou adicionar destinatários, edite essa linha
diretamente (aceita múltiplos e-mails separados por vírgula).


PASSO 4 — O CANDIDATO PREENCHE SEUS DADOS
-------------------------------------------------------------
Antes de rodar a avaliação, o candidato deve editar:

  cypress/fixtures/candidato.json

com o nome completo e e-mail reais dele:

  {
    "nomeCompleto": "Nome Completo do Candidato",
    "email": "candidato@exemplo.com"
  }

Esses dados são preenchidos automaticamente na tela de
identificação da aplicação (pelos Page Objects em
cypress/support/pages/IdentificacaoPage.js) e são os mesmos que
aparecem no e-mail final enviado para o avaliador.


PASSO 5 — DISPARAR O WORKFLOW
-------------------------------------------------------------
O workflow roda automaticamente a cada "git push" em qualquer
branch. Também é possível disparar manualmente:

  Aba "Actions" no GitHub > "Avaliação Cypress" > "Run workflow"

Ao final da execução:
  - o e-mail chega para francisco.marreira@engesoftware.com.br
    com o placar (X de 20 questões aprovadas) e o detalhamento
    de cada questão
  - o relatório completo (HTML) fica disponível para download em
    Actions > (a execução) > Artifacts > "relatorio-cypress"


TESTANDO LOCALMENTE ANTES DE SUBIR
-------------------------------------------------------------
  npm install
  npm run dev          # sobe a aplicação em http://localhost:5173
  npm run cy:open       # abre o Cypress em modo interativo

Para simular exatamente o que roda no CI (build + preview +
Cypress headless, tudo de uma vez):

  npm run build
  npm run test:e2e

O resumo usado no e-mail fica em cypress/relatorio/resumo.json
após qualquer execução local também.
