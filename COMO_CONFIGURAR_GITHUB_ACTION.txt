=============================================================
 COMO CONFIGURAR ESTE PROJETO (GITHUB PAGES + E-MAIL)
=============================================================

O QUE MUDOU EM RELAÇÃO À VERSÃO ANTERIOR
-------------------------------------------------------------
O GitHub Action (.github/workflows/deploy.yml) agora serve SÓ para
publicar a aplicação no GitHub Pages. Ele NÃO roda mais Cypress e NÃO
envia e-mail.

Toda a avaliação (escrever e rodar os "testes" e enviar o relatório)
acontece dentro do próprio site publicado, no navegador do candidato:
ele se identifica, resolve as 20 questões escrevendo código num editor
embutido na tela, e ao clicar em "Finalizar avaliação" a própria
aplicação envia o e-mail com o resultado — direto do navegador, sem
passar pelo GitHub Action. Por isso o e-mail é enviado via EmailJS
(serviço que permite mandar e-mail a partir de JavaScript no navegador,
sem precisar de um servidor/backend).

Existem duas configurações separadas e independentes:
  1) Publicar o site (GitHub Pages)
  2) Fazer o envio de e-mail funcionar (EmailJS)


PASSO 1 — HABILITAR O GITHUB PAGES
-------------------------------------------------------------
No repositório, vá em:
  Settings > Pages > Build and deployment > Source
  Selecione: "GitHub Actions"

Isso é obrigatório e só precisa ser feito uma vez — o workflow
deploy.yml não consegue habilitar isso sozinho.

Depois disso, todo push na branch "main" (ou disparo manual pela aba
Actions) builda e publica o site automaticamente. A URL fica em:
  Settings > Pages (ou https://SEU_USUARIO.github.io/avaliacao/)


PASSO 2 — CRIAR UMA CONTA NO EMAILJS
-------------------------------------------------------------
1. Acesse https://www.emailjs.com/ e crie uma conta gratuita.
2. Em "Email Services", adicione um serviço (Gmail, Outlook, SMTP
   próprio, etc.) e conecte sua conta de e-mail. Anote o "Service ID".
3. Em "Email Templates", crie um novo template. Nele:
   - Defina o destinatário fixo no campo "To Email":
       francisco.marreira@engesoftware.com.br
     (assim o destinatário fica configurado no painel do EmailJS, não
     precisa ficar escrito no código da aplicação)
   - Use estas variáveis no assunto/corpo do template (são exatamente
     as que a aplicação envia — em src/simulador/email/enviarRelatorio.ts):
       {{candidato_nome}}   nome completo do candidato
       {{candidato_email}}  e-mail do candidato
       {{aprovadas}}        quantas questões passaram
       {{total}}            total de questões (20)
       {{resumo}}           relatório completo, questão por questão
   - Sugestão de assunto: "Avaliação Cypress - {{candidato_nome}} - {{aprovadas}}/{{total}}"
   - Sugestão de corpo: use {{resumo}} como corpo principal do e-mail.
   Anote o "Template ID".
4. Em "Account > General", copie a "Public Key".

Em "Account > Security", restrinja os domínios que podem usar essa
chave pública (allowlist) para a URL do seu GitHub Pages, ex:
  SEU_USUARIO.github.io
Isso evita que outra pessoa use sua chave pública fora deste projeto
(a chave pública do EmailJS fica visível no código da aplicação — é
assim que o EmailJS funciona por design, a restrição de domínio é a
proteção recomendada por eles).


PASSO 3 — CRIAR AS SECRETS DO REPOSITÓRIO
-------------------------------------------------------------
As credenciais do EmailJS precisam estar disponíveis no momento do
BUILD (o Vite as embute no código publicado, não são lidas depois em
tempo de execução). Por isso viram secrets do GitHub, usadas pelo
workflow deploy.yml só durante o "npm run build".

No repositório, vá em:
  Settings > Secrets and variables > Actions > New repository secret

Crie estas 3 secrets:
  VITE_EMAILJS_SERVICE_ID    -> o "Service ID" do passo 2
  VITE_EMAILJS_TEMPLATE_ID   -> o "Template ID" do passo 2
  VITE_EMAILJS_PUBLIC_KEY    -> a "Public Key" da sua conta EmailJS

Sem essas secrets, o site publica normalmente, mas o botão "Finalizar
avaliação" não consegue enviar o e-mail automaticamente — nesse caso a
própria aplicação mostra o relatório na tela com um botão "Copiar
relatório", para o candidato enviar manualmente.


PASSO 4 — DISPARAR O DEPLOY
-------------------------------------------------------------
O deploy roda automaticamente a cada push na branch "main". Também dá
para disparar manualmente:
  Aba "Actions" > "Deploy" > "Run workflow"

Depois de mudar as secrets do EmailJS, é preciso rodar o deploy de novo
(push ou disparo manual) para elas entrarem no build publicado.


TESTANDO LOCALMENTE
-------------------------------------------------------------
  npm install
  npm run dev          # http://localhost:5173

Para testar o envio de e-mail localmente, crie um arquivo .env.local
na raiz do projeto (não é versionado no git) com:

  VITE_EMAILJS_SERVICE_ID=...
  VITE_EMAILJS_TEMPLATE_ID=...
  VITE_EMAILJS_PUBLIC_KEY=...

e reinicie o "npm run dev". Sem esse arquivo, o fluxo completo funciona
normalmente, só o envio automático de e-mail fica desativado (mostra o
fallback de copiar o relatório).
